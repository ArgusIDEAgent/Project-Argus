# CodeMind engineering audit

**28 November 2026 · macOS ARM64 · Python 3.14.6 · Node 26.7.0 · VS Code 1.148.0**

The checked-out project can index a repository locally, retrieve and cite saved source, refresh after edits, and reuse its index after restart. The release still misses its documented Python caller and change-impact workflow. In a separate TypeScript fixture, one unfinished file made structural queries for unaffected files unavailable. The Python and extension regression suites passed, so these product failures should become release tests.

The audit used the current working tree, including uncommitted changes over `35c481d`. Runtime checks used disposable repositories, private VS Code profiles and fresh backend processes on separate loopback ports. The existing running engine and repository index served no audit traffic.

## Active project flow

The extension registers a trusted workspace over the session-authenticated loopback API. The engine inventories saved files, stages a repository-local SQLite/FAISS generation, builds structural metadata, checks source consistency and publishes an active snapshot. Chat uses the default `/ask` retrieval and Ollama path. The opt-in hybrid API uses the same snapshot with its own planner, provenance checks and source-navigation handles.

Analyze Change branches from the selected repository into APFS capture of saved JS/TS against Git HEAD, deterministic explanations and static test planning. When execution is enabled and specifically authorized, the runner materializes the reviewed capture in the dedicated VM and reports bounded observations. The two flows share the extension and API session, while capture and execution have their own job and authorization lifecycle.

The default `/ask` returned no structural evidence. Correctly formed hybrid caller and impact requests returned `not_found`. The active snapshot uses the JS/TS parser and bypasses the legacy Python graph builder. The indexing job still reported the graph as ready, with one node and zero relationships. | CM-02 | **P1** | **A common save operation disables structural queries across the repository.** Adding one unfinished TypeScript file preserved the last snapshot on disk but marked it stale. A previously successful caller query on an untouched source returned `stale_index`, and the visible error pointed to engine logs. Removing the file restored the same snapshot and query. [Publication](knowledge_base/synchronization.py#L345) · [Failure status](knowledge_base/synchronization.py#L229) | Track affected files and dependencies, and provide safe partial coverage for unchanged evidence. | CM-03 | **P1** | **Default generated answers can contradict the repository while carrying valid source links.** On the JWT question the model said `routes.py` appeared to have no direct call. The default answer builder verifies source ranges, then appends a list of retrieved ranges to unconstrained prose. [Evidence selection](ai-engine/answers.py#L48) · [Answer and citations](ai-engine/answers.py#L102) | Include complete relevant symbols and graph facts for behavior claims. Render supported structural statements deterministically and label explanation prose clearly. Gate release on correct caller facts and source relevance using real model responses and fixed truth labels. |
| CM-04 | **P1** | **Quick Start and the implementation describe different operating stacks.** The README tells a fresh user to start Docker/Qdrant, obtain an OpenRouter key, and try the legacy CLI. Active indexing uses repository-local SQLite/FAISS and rejects a nonempty `QDRANT_URL`. Default chat uses local Ollama. [Quick Start](README.md#quick-start-living-section--not-covered-by-the-lock) · [Registration](ai-engine/api.py#L376) · [Model call](ai-engine/answers.py#L120) | Provide one verified clean-install path with the backend launcher, VSIX, actual optional runtime dependencies and expected readiness indicators. Check the published instructions on a new environment without old indexes or credentials. |
| CM-05 | **P2** | **Location queries block on generation even when retrieval is already sufficient.** JWT semantic retrieval took 82 ms. Two successful default model answers took 27.2 s and 9.8 s, with the longer one truncated. These are measurements on small fixtures. The default transport waits for the complete Ollama response and applies a 65-second socket timeout. [Synchronous generation](ai-engine/answers.py#L120) | Return exact locations and verified source immediately. Use generation when the question requires an explanation, with an end-to-end deadline and a visible fallback. Track first useful result and total answer time separately. |
| CM-06 | **P2** | **Index refresh and search costs grow with total repository size.** The three-second editor poll calls a freshness check that hashes the repository. The backend also audits registered repositories every five seconds, and default query paths repeat freshness checks. A changed generation copies and validates the previous corpus, while a semantic search loads vector rows and asks FAISS for all ranked IDs before applying the result limit. The small live update took about 1.2 s, re-embedded one chunk, reused one, and pruned one file. Large-repository latency and resource use remain unmeasured. [Editor poll](extension/src/extension.ts#L250) · [Freshness](knowledge_base/synchronization.py#L236) · [Audit worker](knowledge_base/synchronization.py#L456) · [Generation copy](knowledge_base/synchronization.py#L311) · [Vector query](knowledge_base/vector_store.py#L178) | Make the status poll cheap. Share event-based invalidation and retain request-bound evidence validation. Benchmark large fixtures, then bound vector candidate and generation-copy work while checking recall and correct pruning. |
| CM-07 | **P2** | **Repository ownership and refresh scheduling outlive editor selection.** Registered repositories stay in a process-wide map with a cap of 64. The backend watcher adds entries with no per-repository release path. The editor also schedules refreshes from saves, filesystem events and Git polling. Heavy index work shares one global lock, and a manual full rebuild submitted during an incremental job can coalesce into that job and lose its full-rebuild intent. This is a source-review finding. [Registration and cap](ai-engine/api.py#L376) · [Coalescing and global lock](ai-engine/api.py#L218) · [Watcher lifecycle](knowledge_base/synchronization.py#L419) · [Editor refresh](extension/src/extension.ts#L195) | Give open repositories an explicit acquire/release lifecycle. Consolidate refresh scheduling and preserve an explicit rebuild request behind an in-flight job. Test repository churn, close/reopen and full rebuild during refresh. |
| CM-08 | **P2** | **The two answer paths enforce different local-model transport rules.** Hybrid uses a no-proxy, no-redirect opener and rejects cloud-tagged model names. Default `/ask` forwards the configured model to Ollama using standard `urlopen` behavior. The live audit used the installed local model on loopback. [Default transport](ai-engine/answers.py#L120) · [Hybrid transport](query_system/local_ollama.py#L28) | Share a local-only transport and model policy with explicit time and byte budgets. Test the same policy through both entry points, including when HTTP proxy settings are present. |
| CM-09 | **P2** | **Release gates can pass while the production storage and desktop workflow drift.** The ordinary editor suite skips the optional real-source path when its fixture is unset. Enabling that fixture with a fresh current snapshot exposed its legacy global vector journal requirement. The installed VSIX suite checks the editor and fixture API, and native capture and live VM execution run in separate harnesses. This audit found no tracked CI workflow for these gates. [Optional host suite](extension/test/stabilizationRealSuite.js#L28) · [Legacy fixture precondition](ai-engine/tests/stabilization_live_server.py#L29) · [Installed runner](extension/test/runInstalledRelease.cjs) | Make a newly created repository-local snapshot part of the standard editor gate. ## Implementation order

1. Restore the promised Python graph behavior and add a same-fixture release gate through the default editor workflow.
2. Keep verified unaffected answers available during partial indexing, and tighten answer evidence and citation quality.
3. Fix the installation guide and align release tests with current storage and the shipped VSIX.
4. Consolidate refresh ownership and model transport, then use measured repository-size and concurrency results to guide performance changes.
5. Remove default UI dead ends and reconcile branch metadata and packaging warnings.
