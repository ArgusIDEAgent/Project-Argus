# Stabilization S1 — TypeScript resolver crash

S1 corrects the parentless-declaration crash. The affected checkout and real JS/TS
source corpora now build successfully. A frozen copy of the affected checkout also
publishes through the existing knowledge-base pipeline and supports verified
caller retrieval under one pinned generation. Other Phase 10 qualification gaps
(query understanding, local-model quality and default rollout approval) remain
separate work. S1 does not authorize or start those tasks.

## 1. Exact root cause

The failing assumption was in `declaration(symbol)`, originally line 99 of
`semantic_resolver.cjs`: the owner calculation dereferenced `decl.parent.pos`
and `decl.parent.end` for **every** TypeScript symbol declaration.

A TypeScript `SourceFile` is a valid AST root with no parent. The checker returns
it as a declaration for both namespace-module aliases (`import * as lib`) and
CommonJS `exports` symbols. These are valid inputs, not malformed ASTs.

The full affected-checkout replay identified this concrete trigger:

```json
{"usageFile":"extension/test/hybridSuite.js","expression":"exports","symbol":"exports","declarations":[{"kind":"SourceFile","file":"extension/test/hybridSuite.js","parent":null}]}
```

That file's `module.exports = {run}` statement visits the `exports` identifier.
The caller chain is `visit(identifier)` → `targetAt(identifier)` →
`declaration(symbol)` → declaration-owner map → undefined-parent dereference.
For namespace imports, `checker.getAliasedSymbol()` produces the same root kind;
the CommonJS trigger is a direct checker symbol, so it does not require alias
resolution. This distinction was verified rather than inferred from line 99.

The original minimal-run exception was:

```text
TypeError: Cannot read properties of undefined (reading 'pos')
    at semantic_resolver.cjs:99:53
    at Array.map (<anonymous>)
    at declaration (semantic_resolver.cjs:98:39)
    at targetAt (semantic_resolver.cjs:114:10)
    at visit (semantic_resolver.cjs:203:22)
```

The complete instrumented repository replay and stack are stored in
`benchmarks/s1_resolver_results.json`. Its `[eval]` line numbers differ because the
pre-S1 owner expression is replayed with an additional read-only node diagnostic;
the failing expression and declaration kind are the same.

Execution environment: Node **v26.7.0**, installed TypeScript **5.9.3**, project
Python virtual environment. The Python caller is `graph._semantic_pass()`, which
starts a one-shot Node process with `NODE_OPTIONS` cleared and JSON stdin:
`{root, files, configs}`. The compiler host reads only allowlisted inventory files,
uses `allowJs`, `noLib`, no emission and the existing module-resolution options.

No evidence connected this failure to malformed paths, unexpected syntax,
unresolved imports, version incompatibility or cycles. Missing symbols already
return null; parse errors already produce diagnostics. The failing node is a
normal root declaration created by the installed checker.

## 2. Minimal reproduction

One-file CommonJS input:

```js
function run() { return 1; }
module.exports = {run};
```

Two-file TypeScript input:

```ts
// dep.ts
export function run() { return 1; }
// use.ts
import * as lib from './dep';
export function entry() { return lib.run(); }
```

Use a canonical existing temporary directory as `root`, filenames as `files`,
and `configs: []`. `node --test knowledge_base/test_semantic_resolver.cjs` contains
these fixtures. The first namespace regression failed against the original
production resolver before the correction. The CommonJS regression explicitly
replays the old owner calculation and asserts the original exception, while
requiring the corrected resolver to preserve its valid `run()` call.

## 4. Explanation of the minimal fix

```js
const owner = ts.isSourceFile(decl) ? decl : decl.parent;
```

A module root owns itself; other declarations retain their previous parent owner.
The key still contains the source filename and owner's positions. The ambiguity
gate still rejects multiple owners or multiple implementations, and overloads
still prefer their unique implementation. Candidate selection, canonical byte
ranges, graph mapping, symbol IDs, edge semantics and provenance remain unchanged.

There is no broad exception handler, filtering of parentless declarations or
guessed callee. Previously successful named-import, inheritance, nested, CommonJS
and ambiguous cases have identical resolver event/diagnostic output under the
pre-S1 owner calculation. A repeated graph build preserves all symbol/node/edge
identities and graph observations. Pipeline-version invalidation is unnecessary:
successful old inputs keep their semantics; the correction allows previously
crashing inputs to finish.
