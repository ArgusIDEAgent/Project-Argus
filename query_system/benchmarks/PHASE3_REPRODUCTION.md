# Phase 3 qualification evidence

All commands run from the CodeMind project root (its directory name has a trailing
space), using the existing `.venv`, installed Node/VS Code, cached
`BAAI/bge-small-en-v1.5` and configured installed `llama3:latest` only. No model,
runtime dependency or external corpus is downloaded. Copied applications are
parsed as inert source, never imported, trained or launched.

```sh
LITELLM_LOCAL_MODEL_COST_MAP=True .venv/bin/python -m query_system.qualify_phase3 --profile extension --profile react --profile cnn --profile node --profile target --output /tmp/NEW-phase3-corpora
LITELLM_LOCAL_MODEL_COST_MAP=True .venv/bin/python -m query_system.qualify_phase3 --profile extension --profile node --real-model --vscode --source-injection --output /tmp/NEW-phase3-live
LITELLM_LOCAL_MODEL_COST_MAP=True .venv/bin/python -m query_system.qualify_phase3 --profile target --output /tmp/NEW-phase3-target-isolated
.venv/bin/python -m pytest -q
npm --prefix extension test
git diff --check
```

Use new output paths: evidence is written exclusively, never overwritten. A
`completed` profile means the measurement completed, **not that release gates
passed**. Non-passing model/security/performance rows must be inspected. Errors
fail the profile; unavailable measurements are not silently promoted to passes.
TemporaryDirectory cleanup removes only harness-owned private copies/indexes.
Persisted generation/source IDs describe those now-expired copies; they are not
current navigation authority. Original local repositories and user indexes are
not indexing targets. Application hybrid gates remain off by default.

`phase3_cases.json` is the current source-inspected ground truth. Frozen input
versions accompany every run. Historical labels/results are not rewritten:
three initially unqualified Node `readSource` questions were genuinely ambiguous
between `chunker.js` and `registry.js`; the corrected positives specify the file
and a separate ambiguous negative remains. C1 relevance was corrected to include
the directly inspected `extension.ts` delegation. Full mixed-corpus relevance is
not exhaustively labeled, so its semantic precision is unmeasured.

Run inventory hashes, question/requirement/operation diagnostics, original model
HTTP bodies (redactions only), generation contexts, source excerpts, timings,
token telemetry, fail-closed probes, resources and real-host logs are retained
in these directories:

- `phase3_before`: pre-fix lexical cases, before any Phase 3 production edit.
- `phase3_baseline`: original small-source/model/host measurements.
- `phase3_corpora`: first real React/CNN/target profile; includes first indexing
  budget failure. Target original-source comparison notices this task's own
  concurrent edits, not harness writes to the user repository.
- `phase3_final`: router-corrected, pre-compaction model run; includes the
  expanded host's initial missing-result wording assertion failure.
- `phase3_release`: prompt-compaction run; preserves duplicate coverage outputs
  and actual expanded-host success before schema cardinality guidance.
- `phase3_qualified_corpora`: instrumented five-profile sequence; despite the
  historical name this is **not** a qualification pass. It retains cumulative
  peak-RSS and indexing budget failures plus the original Node ambiguity labels.
- `phase3_verified`: schema-guided/prompt-guided actual model repetitions, real
  source injection, corrected Node inputs and actual VS Code scenarios. The name
  means verified measurements, **not production qualification**.
- `phase3_target_isolated`: fresh-process target measurement, separate from
  cumulative multi-profile allocator peaks.
- `phase3_remaining`: shared-session React/CNN/Node rerun, complete necessity
  probes and independently inspected CommonJS graph labels.
- `phase3_node_final`: final real Node add/malformed/recovery/delete publication
  probe, corrected labels and all original results.
- `phase3_review_packet`: incomplete pre-fix review generation (timeout had no
  body); its partial assessment is retained, not a completed review packet.
- `phase3_review`: actual original-output human packet sent for review; pending
  independent scores. Assistant claim annotations are in the separate JSON.
- `phase3_assessment`: machine-readable consolidated metrics and human review
  packet; human approval is never generated by the script.

The harness uses benchmark-only batch 8 / two ONNX threads under unchanged
resource ceilings. Production `EMBED_BATCH=64` is unchanged and is **not**
qualified by those lower-batch measurements. A shared benchmark model avoids
reconstructing native sessions per profile; fresh-process measurements provide
separate RSS attribution. RSS excludes child processes/Ollama; runner RSS and
Ollama resident/unified-GPU memory are recorded separately and must not be added
as independent allocations on Apple unified memory. Sampling is not an OS
resource sandbox or hard cancellation guarantee.

After results exist, reproduce the consolidated assessment with new output:

```sh
LITELLM_LOCAL_MODEL_COST_MAP=True .venv/bin/python -m query_system.assess_phase3 --corpora query_system/benchmarks/phase3_qualified_corpora --extension query_system/benchmarks/phase3_verified/extension.json --model query_system/benchmarks/phase3_verified/extension.json --node query_system/benchmarks/phase3_node_final/node.json --target query_system/benchmarks/phase3_target_isolated/target.json --react query_system/benchmarks/phase3_remaining/react.json --cnn query_system/benchmarks/phase3_remaining/cnn.json --output /tmp/NEW-phase3-assessment
```

Corrected Node and isolated target overlays are described in the final report;
all original rows remain available. Small denominators, repeated prompts and
assistant annotations do not establish held-out accuracy or human usefulness.
The approved provisional budgets are deterministic p95 ≤2 s; warm-model p95
≤30 s; initial publication ≤300 s for ≤3 MiB; Python peak RSS ≤2 GiB.

The read-only live test fixture accepts the test-only `CODEMIND_QUAL_FAULT`
values `model_unavailable`, `model_timeout` and `graph_failure`, set by the host
suite in ephemeral child processes. This is not an application/provider setting,
real model success, or permission to disrupt the user's Ollama service.
