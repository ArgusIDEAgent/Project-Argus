# S2 — Query understanding stabilization

S2 repairs Phase 5 comparison/discovery parsing. The only production file changed
is `query_understanding.py`. Phase 6 routing/operation semantics, Phase 7 evidence
validation, Phase 8 generation, Phase 9 presentation and production-default gates
are unchanged. S3 is not started.

## Root causes and correction

The pre-change audit is in `S2_AUDIT.md`. `parse_question()` split every unquoted
`and` before assigning comparison roles; the single-intent comparison workaround
did not cover compounds. Lowercase operands were absent from mention extraction.
Repeated comparisons could inherit an unrelated earlier target. Prose such as
`function responsible` and `file hashes` became bogus exact names/file scopes;
relative `that` could trigger contextual clarification instead of discovery.

The correction recognizes request boundaries while keeping conjunctions within
comparison operands and functional descriptions. Comparison operands are extracted
by role, with exact spelling, qualified names, quoted references and individual
path scopes preserved. Descriptive discovery is classified before exact mention
extraction, and only genuine source paths become optional filters. A reverse typed
noun match also no longer invents a function called `Find` in `Find function login`.

Canonical resolution is still `_Understanding.symbol()` -> `_Run.symbol()` ->
`metadata.trace()`, under the existing `SnapshotStore.pin_view()`. Symbol-identity,
graph-edge, retrieval and evidence-contract semantics are unchanged; normalization
does not write stored embeddings.

## Compatibility and safeguards

- Original requirements, including repeated intents, remain ordered. Quoted prose,
  code/comment masking, identifier paths containing `and` and descriptive
  conjunctions are not treated as independent instructions.
- `their`, `both` and `them` can refer to a comparison's two already-resolved input
  targets without waiting for deferred prose. A singular `its` reference to a pair
  still requires clarification. Discovery-dependent requirements still depend on
  candidate selection; no candidate, including a single hit, is auto-promoted.
- Phase 6 still defers comparison/explanation. Existing Phase 10 support/generation
  handles those requests; S2 adds no comparison engine or new graph operation.
- `Compare A and B and explain their dependencies` preserves comparison and
  explanation requirements, then represents the dependency summaries as two
  existing one-target `DEPENDENCY_PATH` requirements. This selects two
  `rules.dependency_summary` operations, not a fabricated path from A to B.
- Exact definition/caller/callee questions still select deterministic resolution.
  Missing/ambiguous canonical names retain their original resolution outcomes.
  Explicit unsupported command clauses are retained as unresolved requirements,
  not silently replaced by earlier conversational targets.
- A partially resolvable comparison may show verified evidence for its valid
  operand, while the comparison remains ambiguous and generation makes zero calls.
- Phase 1 contracts and Phase 6 plan validation/roundtrips remain unchanged.

## Remaining language limits and defaults

This remains bounded deterministic recognition, not unrestricted English parsing.
New requirement boundaries use a finite instruction-cue set. A description that
literally uses such a cue after `and` can need quoting/rephrasing; unquoted operands
that look like instruction keywords can be ambiguous. Use explicit pairwise
comparisons and repeat intent words for complex multi-way/elliptical comparisons.
Arbitrary unrecognized verbs and nested discourse are not comprehensively parsed.
Use `defined`/`named` or an explicit symbol kind for exact names that resemble prose.
Recognition retains its 12-entity/requirement cap with explicit warnings. Exact
canonical graph resolution remains JS/TS-only; semantic similarity is not a graph
dependency, runtime behavior proof, test coverage or symbol selection.

The locked root README, dependencies, API defaults, engine internals and embedding
pipeline were not modified. Hybrid mode remains opt-in; no rollout or S3 action
was taken.
